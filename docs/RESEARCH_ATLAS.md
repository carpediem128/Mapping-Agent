# 联系漏斗与主题网络

## 使用入口

- 联系总表 `/#contacts`：左侧选择行业，右侧查看漏斗，下方查看同步筛选后的公司明细。
- 主题网络 `/#topic-network`：主题球支持旋转、缩放和暂停；点击节点或右侧主题名称进入一级公司网络。选择公司后展示研究字段及来源文件、sheet 和行号。
- 行业统计不再单设页面，旧 `#industries` 路由兼容跳转到联系总表。保留原有页面编号，新增入口编号为 08。

## 统计口径

联系数据使用 `site_data.json` 的 `contact_progress.rows`，按去除空白、转小写后的公司名称精确去重，保留原名称和多行业归属，不进行模糊实体合并。全体公司去重计数，跨行业企业可能出现在多个行业中，行业合计不能直接当作全体公司数。

漏斗是当前状态快照，不表示同一批次随时间推进的转化率。每条刻度对应一家企业，大数据量时会注明每刻度代表的数量。`未联系上`、`待回复`、`已发邮件`、`已致电`、`被拒绝`计入尝试联系；仅明确的已联系、已加微信、有接触、可进一步沟通或约见记录计入建立联系。单独的“业务不相关”不推断为已经联系。未填写约见不计为否，单独报告未记录数量。有联系方式另列，不作为联系成功证据。

主题网络从 `mapping_sources.json` 中 sheet 为“一级市场”的记录构建，以文件的主题名称分组。每个主题内按公司名精确去重；导入记录数、主题内公司数和跨主题唯一公司数分别展示。主题球大小随公司数量的平方根变化；公司网络的边只表示主题归属，不表示供应商、投资或合作关系。深色公司已建立联系，浅绿有联系方式，灰色未匹配联系记录。

## 实现与设计参考

- `web/workspace_model.mjs`：纯函数归一化、去重、联系状态分类和主题模型。
- `web/contact_funnel.mjs`：SVG 刻度与连接流线，行业筛选联动已有明细表。
- `web/topic_network.mjs`：Three.js 0.170.0、OrbitControls 与 D3 7.9.0 的确定性 force 布局，原生 DOM 提供可访问列表。
- `web/research_atlas.css`：沿用现有象牙白/橄榄绿界面，移动端将公司列表放在画布下方。
- 第三方依赖随站点本地提供，许可证在 `web/vendor/`，没有新增付费 API 或运行时 CDN 依赖。

已安装并参考 lieflat-charts（作者“躺在废墟里”）。用户指定的 HTTPS npx 安装首次失败后，改为 SSH 拉取同一仓库，再通过 npx 从本地路径安装到 `.agents/skills/lieflat-charts`。筛选了 L13 Hourglass Stream、B2 hub/satellite、L5 radial convergence、L6 cluster 等模板；采用 L13 的刻度和流线表达联系阶段，采用 B2 的主题中心与公司卫星布局。L5/L6 不适合阶段数量和逐公司查询，未采用。球形导航遵循本次明确需求，是对技能默认二维建议的定向扩展；配色沿用既有产品设计。

画布仅在页面可见时持续绘制，支持暂停自动旋转和系统减少动态效果设置。WebGL 不可用时保留列表和详情；三维节点不作为唯一操作入口。
